01

Classes & Objects

Class = a logical blueprint / template. Object = a physical instance occupying heap memory. Objects have three essential properties: State (fields), Identity (memory address makes it unique), and Behavior (methods).

class Student {
    // State (fields)
    String name;
    int    rno;
    float  marks;

    // Behavior (methods)
    void greeting() {
        System.out.println("Hello, I am " + name);
    }
}

// Creating objects
Student s1 = new Student();  // 's1' is a reference, object lives on heap
Student s2 = s1;              // s2 and s1 point to THE SAME object — NO copy!
⚠️
Reference vs Object: Assigning s2 = s1 copies the reference, not the object. Both variables point to the same heap location. Mutating via s2 changes what s1 sees.

The new Keyword — How it works

🖥
Compiler (LHS)

Checks if class Student exists. Declares reference variable s1. Initially it's null.

⚙️
JVM (RHS — new)

Allocates heap memory for the object, calls the constructor, returns the object's reference which gets stored in s1.

Dot Operator .

Accesses instance members on an object or static members via class name.

s1.name = "Gauri";     // instance field
s1.greeting();        // instance method
Math.sqrt(16);         // static method via class name
02

Constructors, this & final

A constructor initialises an object the moment it's created. No return type, same name as class. Called automatically by new.

①
Default

No parameters. JVM provides one if you don't declare any constructor at all.

②
Parameterised

Takes arguments to set field values at creation time.

③
Copy

Takes an object of the same class and copies its fields (manual in Java, unlike C++).

class Student {
    int rno; String name; float marks;

    // Default — chains to parameterised using this()
    Student() { this(0, "default", 0); }

    // Parameterised
    Student(int rno, String name, float marks) {
        this.rno   = rno;
        this.name  = name;
        this.marks = marks;
    }

    // Copy constructor
    Student(Student other) {
        this.rno   = other.rno;
        this.name  = other.name;
        this.marks = other.marks;
    }
}

The this Keyword

  • Refers to current object — resolves name collision between local param and field.
  • this() — calls another constructor of the same class (constructor chaining). Must be first statement.

The final Keyword

Used OnEffectKey Point
final variableValue can't be reassignedPrimitives → value frozen. Reference → can't re-point, but object's fields can still change.
final methodCan't be overriddenEnables early (compile-time) binding → performance boost via inlining.
final classCan't be extended (subclassed)Implicitly makes all methods final. Can't be both abstract + final.

The finalize() Method

Called by the Garbage Collector just before an object is reclaimed. Use to release non-Java resources. Deprecated in Java 9+ — prefer try-with-resources.

🎯 Interview Tip

Interviewers love asking: "Can a constructor be private?" — Yes! That's the backbone of the Singleton pattern. Also know: constructors are not inherited, but super() chains them.

Constructor Chaining with Inheritance

class Base {
    Base() { System.out.println("Base"); }
}
class Derived extends Base {
    Derived() {
        // super() called implicitly here — Base constructor runs first
        System.out.println("Derived");
    }
}
// Output: Base  →  Derived
🔴
If the superclass has only parameterised constructors, the subclass must explicitly call super(args) — otherwise a compile error occurs.

Inheritance

Inheritance lets a subclass acquire the properties and behaviours of a superclass. Use extends. Java supports single inheritance only (no multiple class inheritance).

TypeStructureJava Support?
SingleA → B✓ Yes
MultilevelA → B → C✓ Yes
HierarchicalA → B, A → C✓ Yes
MultipleA + B → C (two parents)✗ Classes No / ✓ Via Interfaces
HybridMix of above✗ Classes No / ✓ Via Interfaces
class Box {
    private double width, height, depth;

    Box(double w, double h, double d) {
        width = w; height = h; depth = d;
    }
    double volume() { return width * height * depth; }
}

class BoxWeight extends Box {
    double weight;

    BoxWeight(double w, double h, double d, double m) {
        super(w, h, d); // call superclass constructor
        weight = m;
    }
}

The super Keyword — Two Uses

①
super() — Call parent constructor

Must be the first statement in the subclass constructor. Always refers to the immediate parent.

②
super.member — Access shadowed member

Access a field or method of the superclass that's been hidden/overridden by the subclass.

Superclass Reference → Subclass Object

Box plainBox = new BoxWeight(1,2,3,4);
// plainBox can ONLY access Box members, not 'weight'
// But at runtime, overridden methods resolve to BoxWeight version (polymorphism)
💡
It is the type of the object, NOT the reference variable, that determines which overridden method executes at runtime. The reference type determines which members are accessible at compile time.
⚠️
Polymorphism does NOT apply to instance variables — only to methods. Variable access is resolved at compile time based on reference type.
04

Polymorphism

Poly = many, Morphism = forms. One interface, multiple implementations. Java achieves it in two ways:

①
Compile-Time (Static)

Method Overloading — same method name, different parameter list. Resolved by the compiler. Also called early binding.

②
Runtime (Dynamic)

Method Overriding + Dynamic Dispatch — resolved by JVM at runtime based on actual object type. Also called late binding.

Method Overloading

Same name, different parameters. Return type alone is not sufficient to overload.

class Calc {
    int    add(int a, int b)               { return a + b; }
    double add(double a, double b)         { return a + b; }
    int    add(int a, int b, int c)        { return a + b + c; }
}

// Auto type promotion: if test(int) not found, Java tries test(double)

Method Overriding & Dynamic Dispatch

class Animal {
    void sound() { System.out.println("..."); }
}
class Dog extends Animal {
    @Override
    void sound() { System.out.println("Woof"); }
}
class Cat extends Animal {
    @Override
    void sound() { System.out.println("Meow"); }
}

Animal a = new Dog();
a.sound(); // "Woof" — determined at RUNTIME by actual object type

a = new Cat();
a.sound(); // "Meow"

static methodsCan overloadCannot override (method hiding)
private/finalCan overloadCannot override
📌
Covariant Return Type: If B extends A, an overriding method in B can return type B where parent returned A.
05

Abstraction

Hiding implementation details, exposing only the what, not the how. Achieved in Java via Abstract Classes and Interfaces.

Abstract Classes

  • Declared with abstract keyword.
  • Cannot be instantiated (no objects), but can hold references.
  • Can have abstract methods (no body) AND concrete methods (with body).
  • No abstract constructors or abstract static methods.
  • Subclass must implement all abstract methods — or it must also be declared abstract.
abstract class Shape {
    String color;

    Shape(String color) { this.color = color; }  // concrete constructor

    abstract double area();          // subclass MUST implement
    abstract double perimeter();

    void display() {               // concrete method
        System.out.println("Color: " + color);
    }
}

class Circle extends Shape {
    double r;
    Circle(String c, double r) { super(c); this.r = r; }

    @Override double area()      { return Math.PI * r * r; }
    @Override double perimeter() { return 2 * Math.PI * r; }
}

Shape s = new Circle("Red", 5);  // ✅ superclass ref to subclass object
🎯 Interview Tip

A public constructor on an abstract class is technically valid (abstract classes can have constructors for subclass chaining), but it makes little sense because you can never call new AbstractClass() directly. Interviewers love this nuance.

06

Encapsulation

Bundling data (fields) and methods that operate on that data within one unit (class), and restricting direct access from outside. Achieved via private fields + public getters/setters.

class BankAccount {
    private double balance;   // hidden

    public double getBalance()         { return balance; }
    public void   deposit(double amt)  { if (amt > 0) balance += amt; }
    public void   withdraw(double amt) {
        if (amt > 0 && amt <= balance) balance -= amt;
        else throw new IllegalArgumentException("Insufficient funds");
    }
}
💡
Encapsulation vs Abstraction: Encapsulation = how you hide the data (access control + getters/setters). Abstraction = what you expose (the interface/contract). Encapsulation is a mechanism, Abstraction is a design principle.

Protected — the Tricky One

// package one
class Base { protected void display() { } }

// package two
class Derived extends Base {
    void show() {
        display();                // ✅ via inheritance (current object)
        new Derived().display();  // ✅ Derived type — allowed
        new Base().display();     // ❌ Base type in diff package — NOT allowed
    }
}
⚠️
Protected allows access through a Derived-type reference outside the package. A Base-type reference in a different package does NOT get access even inside a subclass.
08

static Keyword

static members belong to the class, not to any instance. They exist even before any object is created.

📦
Static Variable

One copy shared across all objects. Stored in method area (class area), not heap per object.

⚡
Static Method

Can be called without object. Cannot access instance variables or use this/super. Can only call other static methods directly.

class Counter {
    static int count = 0;   // shared across all objects
    Counter() { count++; }
    static int getCount() { return count; }
}

Counter c1 = new Counter();
Counter c2 = new Counter();
System.out.println(Counter.getCount()); // 2

Static Block

Executed once when the class is first loaded. Used for complex static initialisation.

class Config {
    static final String DB_URL;
    static {
        // runs once at class load time
        DB_URL = "jdbc:mysql://localhost/mydb";
        System.out.println("Class loaded");
    }
}
📌
Only nested (inner) classes can be static. Top-level classes cannot be static. Static nested classes do NOT have a reference to the outer class instance.
🔴
Static methods cannot be overridden — they are resolved at compile time (method hiding). Static interface methods are not inherited by implementing classes or sub-interfaces.
09

Interfaces

An interface is a pure contract — specifies what a class does, not how. Solves the multiple inheritance problem.

📋
Default Rules

All methods: public abstract by default.
All variables: public static final by default (must be initialised).

🔌
Multiple Implementation

A class can implement multiple interfaces. An interface can extend multiple interfaces.

interface Flyable {
    int MAX_SPEED = 1000;           // public static final — implicitly
    void fly();                      // public abstract — implicitly

    default void land() {           // Java 8+ default method
        System.out.println("Landing...");
    }

    static void info() {            // Java 8+ static method — NOT inherited
        System.out.println("Flyable interface");
    }
}

interface Swimmable { void swim(); }

class Duck implements Flyable, Swimmable {
    @Override public void fly()  { System.out.println("Duck flying"); }
    @Override public void swim() { System.out.println("Duck swimming"); }
}

Default Method Conflict Resolution Rules

  1. Class impl wins over interface default — if the class provides the method, that's used.
  2. Two interfaces with same default → compile error unless the class overrides the method.
  3. Child interface default wins over parent interface default.
🎯 Interview Tip

Key question: "Why can't interfaces have instance variables?" — Because variables in interfaces are static final. They're class-level constants, not state. Interfaces model capabilities (contracts), not state machines.

Abstract Classes (Deep Dive)

Key Rules at a Glance

  • Declared with abstract. Cannot instantiate with new.
  • Can have abstract methods (no body) and concrete methods (with body).
  • No abstract constructors. No abstract static methods. (Can have static methods though.)
  • Any subclass must implement ALL abstract methods, or itself be abstract.
  • Can be used as a reference type for runtime polymorphism.
  • Cannot be both abstract and final.
abstract class Vehicle {
    String brand;

    Vehicle(String brand) { this.brand = brand; }

    abstract void fuelType();    // must be overridden

    void start() { System.out.println(brand + " started"); } // concrete
}

class Car extends Vehicle {
    Car(String b) { super(b); }
    @Override void fuelType() { System.out.println("Petrol/Diesel"); }
}

Vehicle v = new Car("Toyota");   // ✅ superclass ref
v.start();     // Toyota started
v.fuelType(); // Petrol/Diesel  ← runtime dispatch

Enums

An enum is a special class representing a group of named constants. Internally each constant is a public static final instance of the enum class.

enum Day {
    MON, TUE, WED, THU, FRI, SAT, SUN;
    // each is: public static final Day MON = new Day();
}

Day d = Day.MON;
System.out.println(d);                  // MON
System.out.println(d.ordinal());        // 0 (index)
System.out.println(d.name());           // "MON"
Day[] all = Day.values();               // array of all constants
Day fri = Day.valueOf("FRI");           // from string

Enum with Constructor & Methods

enum Planet {
    MERCURY(3.303e+23, 2.4397e6),
    VENUS  (4.869e+24, 6.0518e6),
    EARTH  (5.976e+24, 6.37814e6);

    private final double mass, radius;

    // constructor MUST be private or package-private
    Planet(double mass, double radius) {
        this.mass = mass; this.radius = radius;
    }

    double surfaceGravity() { return 6.67300E-11 * mass / (radius * radius); }
}
RuleDetail
ExtendsImplicitly extends java.lang.Enum. Cannot extend anything else. Cannot be superclassed.
ImplementsCan implement multiple interfaces.
ConstructorMust be private or default (not public/protected).
MethodsConcrete only — no abstract methods.

Inner Classes

①
Non-static Inner Class

Has access to outer class instance members. Requires outer class instance to instantiate: outer.new Inner()

②
Static Nested Class

No implicit reference to outer class. Can have static variables. Instantiate as: new Outer.Nested()

③
Local Inner Class

Defined inside a method. Scope limited to that method. Can access final/effectively-final local vars.

④
Anonymous Inner Class

No name. Defined and instantiated in one expression. Common in event listeners / functional interfaces before lambdas.

class Outer {
    private int x = 10;

    // Non-static inner — can access x
    class Inner { void show() { System.out.println(x); } }

    // Static nested — cannot access x directly
    static class Nested { void hello() { System.out.println("Hi"); } }
}

// Usage
Outer o = new Outer();
Outer.Inner  i = o.new Inner();   // non-static
Outer.Nested n = new Outer.Nested(); // static nested

// Anonymous inner class
Runnable r = new Runnable() {
    @Override
    public void run() { System.out.println("Running"); }
};
// Modern Java: use lambda instead → () -> System.out.println("Running")
📌
Only nested classes can be static. Top-level classes can never be static. Outermost class itself cannot be static.

Packages

Packages are containers for classes that provide naming and visibility control. They prevent name collisions and organise code hierarchically.

package com.company.utils;  // declares package — must be first statement

import java.util.ArrayList;  // import specific class
import java.util.*;          // import all public classes in package
  • Package structure mirrors directory structure on disk.
  • JVM finds packages via: current working directory → CLASSPATH env var → -classpath flag.
  • Only public classes in a package are accessible to code in other packages.
  • default (no modifier) = package-private: accessible only within the same package.
// com.company1.Employee and com.company2.Employee can coexist
com.company1.Employee e1 = new com.company1.Employee();
com.company2.Employee e2 = new com.company2.Employee();

Singleton Design Pattern

Ensures a class has only one instance across the entire application. Widely used for DB connections, logging, config managers.

public class Singleton {
    // 1. private static instance holder
    private static Singleton instance;

    // 2. private constructor — prevents external instantiation
    private Singleton() { }

    // 3. public static factory method
    public static Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}

Singleton a = Singleton.getInstance();
Singleton b = Singleton.getInstance();
System.out.println(a == b);  // true — same object!

Thread-Safe Singleton

public class Singleton {
    // volatile ensures visibility across threads
    private static volatile Singleton instance;

    private Singleton() { }

    public static Singleton getInstance() {
        if (instance == null) {                    // first check
            synchronized (Singleton.class) {
                if (instance == null) {             // double-check
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}

Wrapper Classes & Pass-by-Value

Java passes everything by value. For primitives, the value is copied. For objects, the reference value is copied (not the object).

// Why this swap doesn't work
static void swap(Integer a, Integer b) {
    Integer temp = a; a = b; b = temp;  // local references reassigned, originals unchanged

The Object Class

Every class in Java implicitly extends java.lang.Object. It sits at the root of the entire Java class hierarchy. Knowing its methods cold is mandatory for FAANG interviews.

The equals() + hashCode() Contract

🔴
Golden Rule: If you override equals(), you MUST override hashCode(). Objects that are equal must have the same hash code. Violating this breaks HashMap, HashSet, and every hash-based collection.
class Student {
    int id; String name;

    Student(int id, String name) { this.id = id; this.name = name; }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;                  // same reference
        if (o == null || getClass() != o.getClass()) return false;
        Student s = (Student) o;
        return id == s.id && Objects.equals(name, s.name);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id, name);  // consistent with equals
    }

    @Override
    public String toString() {
        return "Student{id=" + id + ", name='" + name + "'}";
    }
}

// Without override: two different objects with same data would be "not equal"
Student s1 = new Student(1, "Gauri");
Student s2 = new Student(1, "Gauri");
System.out.println(s1.equals(s2));   // true  (after override)
System.out.println(s1 == s2);        // false (different refs always)

Shallow vs Deep Copy with clone()

📋
Shallow Copy

Default clone() behaviour. Copies primitive fields by value but copies references — both original and clone point to the same nested objects.

📋
Deep Copy

Override clone() and also clone all nested reference-type fields. Or use a copy constructor / serialisation.

class Address { String city; }
class Person implements Cloneable {
    String name;
    Address addr;

    // Deep clone
    @Override
    protected Person clone() throws CloneNotSupportedException {
        Person copy = (Person) super.clone(); // shallow
        copy.addr = new Address();            // deep — new nested object
        copy.addr.city = this.addr.city;
        return copy;
    }
}

Casting & instanceof

⬆
Upcasting

Subclass → Superclass. Implicit / automatic. Always safe. Access restricted to superclass members at compile time.

⬇
Downcasting

Superclass → Subclass. Explicit cast required. Unsafe — throws ClassCastException at runtime if the object is not actually that subtype. Always check with instanceof first.

class Animal { void eat() { } }
class Dog extends Animal { void bark() { } }
class Cat extends Animal { }

// Upcasting — implicit, safe
Animal a = new Dog();    // Dog IS-A Animal ✅

// Downcasting — explicit, risky
Dog d = (Dog) a;         // ✅ safe because a actually holds a Dog
d.bark();

// ClassCastException at runtime:
Animal a2 = new Cat();
Dog d2 = (Dog) a2;       // ❌ ClassCastException! a2 is actually a Cat

// Safe downcasting with instanceof
if (a instanceof Dog) {
    Dog dog = (Dog) a;
    dog.bark();
}

// Java 16+ Pattern Matching instanceof (cleaner!)
if (a instanceof Dog dog) {    // declares 'dog' in one step
    dog.bark();                 // no explicit cast needed
}
💡
instanceof returns false if the reference is null. It checks: "Is this object an instance of this class OR any of its subclasses?" — so dog instanceof Animal is also true.

Garbage Collection & Memory Model

Understanding where objects live and how they get cleaned up is critical for writing efficient Java and for interviews at scale-focused companies.

📦
Stack Memory

Stores local variables and method call frames (including reference variables). Fast LIFO access. Memory released automatically when method returns. Each thread has its own stack.

🏗
Heap Memory

Stores all objects created with new. Shared across all threads. Managed by the Garbage Collector. Larger but slower than stack. Divided into Young Gen, Old Gen, and Metaspace (Java 8+).

void method() {
    int x = 5;              // x lives on STACK
    Student s = new Student(); // reference 's' on stack, object on HEAP
}   // s goes out of scope → object becomes eligible for GC

Garbage Collection — Key Facts

  • GC runs automatically — you cannot force it (calling System.gc() is only a hint).
  • An object is GC-eligible when no live references point to it.
  • GC uses algorithms like Mark-and-Sweep, Generational GC (Young → Old promotion), and G1 GC (default Java 9+).
  • finalize() is called before collection — but deprecated in Java 9 and removed in Java 18. Use try-with-resources and AutoCloseable instead.
Heap RegionHoldsGC Type
Young Generation (Eden + Survivor)Newly created objectsMinor GC (fast)
Old Generation (Tenured)Long-lived objects promoted from YoungMajor/Full GC (slow — causes pauses)
Metaspace (Java 8+)Class metadata, static variablesCleaned when class is unloaded
String Pool (in Heap)Interned String literalsSubject to GC if unreachable
⚠️
Memory Leak in Java: Can happen when objects are kept alive unintentionally — e.g., static collections holding references, unclosed streams, listeners not deregistered. GC cannot collect objects that still have reachable references even if logically "done".
20

String, Immutability & String Pool

String in Java is a class (not a primitive), and it is immutable — once created, its value cannot change. Every "modification" creates a new String object.

// String literal → goes into String Pool (heap)
String s1 = "hello";
String s2 = "hello";         // same pooled object as s1
System.out.println(s1 == s2);  // true — same reference from pool

// new keyword → always creates a NEW heap object (bypasses pool)
String s3 = new String("hello");
System.out.println(s1 == s3);     // false — different objects
System.out.println(s1.equals(s3)); // true  — same content

// intern() — forces into pool
String s4 = s3.intern();
System.out.println(s1 == s4);     // true — now in pool

Why is String Immutable?

  • Security — strings used in network connections, file paths, DB URLs can't be tampered with.
  • Thread safety — immutable objects are inherently thread-safe without synchronisation.
  • String Pool — pooling only works safely if strings can't change after being shared.
  • HashCode caching — String caches its hashCode on first call (since value never changes).

String vs StringBuilder vs StringBuffer

ClassMutable?Thread-Safe?PerformanceUse When
String❌ No✅ Yes (immutable)Slow for concatenation in loopsFixed strings, keys, literals
StringBuilder✅ Yes❌ NoFastSingle-threaded string building
StringBuffer✅ Yes✅ Yes (synchronized)Slower than StringBuilderMulti-threaded string building
// Bad — creates N intermediate String objects in loop
String result = "";
for (int i = 0; i < 1000; i++) result += i;  // O(n²) memory!

// Good — single mutable buffer
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 1000; i++) sb.append(i);
String result = sb.toString();

Comparable vs Comparator

Both are interfaces used for sorting objects. This is one of the most frequently asked Java OOP questions in FAANG interviews.

①
Comparable — Natural Ordering

Interface: java.lang.Comparable<T>
Method: int compareTo(T o)
Implemented inside the class being sorted. Defines the default/natural order.

②
Comparator — Custom Ordering

Interface: java.util.Comparator<T>
Method: int compare(T o1, T o2)
Implemented outside the class. Defines alternate orderings without modifying the class.

// ── Comparable — "I know how to compare myself" ──
class Student implements Comparable<Student> {
    String name; int marks;

    @Override
    public int compareTo(Student other) {
        return this.marks - other.marks;  // ascending by marks
        // return 0  → equal
        // return <0 → this comes before other
        // return >0 → this comes after other
    }
}

List<Student> list = new ArrayList<>();
Collections.sort(list);            // uses compareTo


// ── Comparator — "An external judge decides order" ──
Comparator<Student> byName = (s1, s2) -> s1.name.compareTo(s2.name);
Comparator<Student> byMarksDesc = (s1, s2) -> s2.marks - s1.marks;

Functional Interfaces & Lambdas

Java 8 blended OOP with functional programming. A Functional Interface has exactly one abstract method. Lambdas are anonymous implementations of functional interfaces — they make the code dramatically shorter.

@FunctionalInterface
interface Greeting {
    void greet(String name);    // exactly one abstract method
    // can still have default/static methods
}

// Old way — anonymous inner class
Greeting g1 = new Greeting() {
    public void greet(String name) { System.out.println("Hello " + name); }
};

// Java 8 Lambda — clean, concise
Greeting g2 = name -> System.out.println("Hello " + name);
g2.greet("Gauri");

Records & Sealed Classes (Modern Java)

Records (Java 16+ — stable)

Records are immutable data carrier classes. The compiler auto-generates: constructor, getters (by field name, no "get" prefix), equals(), hashCode(), and toString().

// Traditional data class — lots of boilerplate
class Point {
    private final int x, y;
    Point(int x, int y) { this.x = x; this.y = y; }
    public int x() { return x; }
    public int y() { return y; }
    // + equals, hashCode, toString...
}

// Record — everything above in one line!
record Point(int x, int y) { }

Point p = new Point(3, 4);
p.x();          // 3
p.y();          // 4
System.out.println(p);   // Point[x=3, y=4]

// Records can have compact constructors for validation
record Range(int min, int max) {
    Range {   // compact constructor
        if (min > max) throw new IllegalArgumentException();
    }
}
💡
Records are implicitly final (cannot be extended). Fields are private final. Records can implement interfaces. They cannot extend classes (already extend java.lang.Record).

Sealed Classes (Java 17+ — stable)

Sealed classes restrict which classes can extend them. This gives exhaustive type hierarchies — the compiler knows all possible subtypes.

// Only Circle, Rectangle, Triangle can extend Shape
public sealed class Shape
    permits Circle, Rectangle, Triangle { }

// Permitted subclasses must be: final, sealed, or non-sealed
public final class    Circle    extends Shape { double radius; }
public sealed class   Rectangle extends Shape permits Square { }
public non-sealed class Triangle extends Shape { }  // open to anyone

// Java 21 pattern matching switch — exhaustive, no default needed!
double area = switch (shape) {
    case Circle    c -> Math.PI * c.radius * c.radius;
    case Rectangle r -> r.width * r.height;
    case Triangle  t -> /* ... */ 0;
};
🎯 Interview Tip

Sealed classes + pattern matching switch together replace the classic "visitor pattern" boilerplate. This is a favourite "modern Java OOP" question at senior SDE interviews. Knowing Java 14–21 features signals seriousness.

🎯 FAANG Interview Q&A

🏆 Top Must-Know Questions

These are the highest-frequency OOPs questions asked at Google, Amazon, Meta, Apple, Microsoft, Flipkart, and other top product companies.

Q
What are the 4 pillars of OOP?

Encapsulation (hide data via access modifiers + getters/setters) → Abstraction (expose only what's needed via abstract/interfaces) → Inheritance (reuse via extends/implements) → Polymorphism (one interface, many forms — overloading + overriding).

Q
Why does Java not support multiple class inheritance?

The Diamond Problem — if two parent classes have the same method, the JVM can't decide which to call. Java solves this with interfaces (which have explicit conflict resolution rules).

Q
Can we override static methods? Can we overload them?

Static methods cannot be overridden (they're resolved at compile time — method hiding, not polymorphism). They can be overloaded (different parameters in same class).

Q
What is the difference between method hiding and method overriding?

Overriding: Non-static method in subclass with same signature — resolved at runtime (dynamic dispatch). Hiding: Static method in subclass with same signature — resolved at compile time based on reference type, not object type.

Q
Can abstract class have constructor?

Yes! Abstract classes can (and should) have constructors, used for subclass chaining via super(). But you cannot instantiate an abstract class directly with new.

Q
Can interface have constructors?

No. Interfaces cannot have constructors because they cannot be instantiated.

Q
What is the difference between == and .equals()?

== checks reference equality (same memory address). .equals() checks logical/value equality (overridden in String, Integer, etc.). For primitive comparisons, use == always.

Q
What is Covariant Return Type?

An overriding method in a subclass can return a subtype of the parent method's return type. E.g., parent returns Animal, child can return Dog (if Dog extends Animal).

Q
What is the difference between early and late binding?

Early (static) binding: Method resolved at compile time — overloaded methods, final/private/static methods. Late (dynamic) binding: Method resolved at runtime — overridden instance methods via dynamic dispatch.

Q
Is Java pass-by-value or pass-by-reference?

Java is always pass-by-value. For primitives, the value is copied. For objects, the reference value (address) is copied — the method gets its own copy of the reference, so reassigning it doesn't affect the caller, but mutating the object through it does.

Q
When to use abstract class vs interface?

Use abstract class when related classes share code/state (IS-A with shared implementation). Use interface when unrelated classes need to implement a capability (CAN-DO/HAS-A capability). From Java 8, interfaces can have default methods, blurring lines — but the principle remains.

Q
What happens if two interfaces have the same default method and a class implements both?

Compile error — the class must override the method to resolve the ambiguity. The compiler cannot pick between the two default implementations.

Q
Can we make an enum implement an interface?

Yes! Enum can implement interfaces. But enum cannot extend any class (it already implicitly extends java.lang.Enum). Enum cannot be a superclass.

Q
What is dynamic method dispatch?

The mechanism by which an overridden method call is resolved at runtime based on the actual type of the object (not the reference type). It's the foundation of runtime polymorphism. The JVM uses the vtable to achieve this.

Q
Explain the Singleton pattern and its thread-safety issues.

Basic (lazy) singleton is not thread-safe — two threads may simultaneously see instance == null and create two objects. Fix with double-checked locking (volatile + synchronized) or use Enum singleton (inherently thread-safe and serialization-safe).

// Best — Enum singleton (Josh Bloch, Effective Java)
enum DatabaseConnection {
    INSTANCE;
    public void connect() { /* ... */ }
}
Q
What is the contract between equals() and hashCode()?

If a.equals(b) is true, then a.hashCode() == b.hashCode() must be true. The reverse is NOT required (hash collision is OK). Breaking this contract causes bugs in HashMap, HashSet etc. — objects that are logically equal won't be found after insertion.

Q
What is the difference between String, StringBuilder, StringBuffer?

String is immutable and thread-safe (by immutability). StringBuilder is mutable + not thread-safe (fastest for single-thread string building). StringBuffer is mutable + thread-safe (synchronized methods, slower). In loops always use StringBuilder.

Q
Why is String stored in a pool? What is String interning?

String literals are stored in the String Pool (part of heap, Metaspace before Java 7) to save memory — identical literals share one object. intern() forces a heap String object into the pool so reference equality (==) works with pool strings. Always use .equals() for String comparison in production code.

Q
What is the difference between upcasting and downcasting?

Upcasting (Subclass → Superclass ref): always implicit and safe. Access limited to superclass API. Downcasting (Superclass ref → Subclass): explicit cast required, unsafe — throws ClassCastException at runtime if actual object isn't that type. Always guard with instanceof (or pattern matching instanceof in Java 16+).

Q
What is a Functional Interface? Can it have multiple methods?

A Functional Interface has exactly one abstract method. It can also have any number of default and static methods — those don't count. Annotate with @FunctionalInterface (optional but recommended — compiler enforces the rule). Lambdas are syntactic sugar for implementing functional interfaces.

Q
Comparable vs Comparator — when to use which?

Use Comparable when there is one natural/default ordering for the class (e.g., Student by marks) and you can modify the class. Use Comparator when you need multiple orderings, or cannot modify the class (third-party), or want the ordering logic decoupled. Comparator can be passed as a lambda from Java 8 onwards.

Q
Where do objects live? What is Stack vs Heap?

Stack: local variables, method frames, reference variables (fast, LIFO, thread-private). Heap: all objects created with new (managed by GC, shared across threads). A reference variable on the stack points to an object on the heap. When a method returns, its stack frame is popped — if no other references point to the heap object, it becomes GC eligible.

Q
Can we prevent garbage collection of an object?

Keep at least one strong reference to the object alive. Java also has SoftReference, WeakReference, and PhantomReference (java.lang.ref) for caches that GC can reclaim under memory pressure. You cannot truly "prevent" GC — you can only ensure an object is reachable.

Q
What are Records and when would you use them?

Records (Java 16+) are immutable data carrier classes where the compiler auto-generates the canonical constructor, accessors (by field name), equals(), hashCode(), and toString(). Use them for DTOs, value objects, response/request models — anywhere you just need to hold data without behaviour. They cannot extend classes and are implicitly final.

Q
What problem do Sealed Classes solve?

They restrict which classes can extend a class/interface, giving the compiler knowledge of the complete closed type hierarchy. This enables exhaustive pattern matching in switch expressions without a default branch. They replace ad-hoc approaches like package-private constructors or documentation-only restrictions.

Q
What is shallow copy vs deep copy?

Shallow copy: copies primitive fields by value, but reference fields by reference — both original and copy share the same nested objects. Deep copy: recursively copies all nested objects too — completely independent duplicate. Default clone() is shallow. Implement deep copy manually via overridden clone(), copy constructors, or serialization.

Q
What is the role of the Object class?

Every class in Java implicitly extends java.lang.Object. It provides: equals(), hashCode(), toString(), clone(), getClass(), finalize(), wait(), notify(), notifyAll(). FAANG frequently asks you to override equals() + hashCode() correctly.
